# OneDoor web

Human-owned file. Agents: do not edit this file. Propose changes to the human instead.
Read `/AGENTS.md` first. Its hard rules apply here.

## Stack

- TanStack Start (React), Node 26, pnpm
- shadcn/ui with Tailwind CSS
- Apollo Client 4 with `@apollo/client-integration-tanstack-start`
- GraphQL Code Generator producing typed documents (`TypedDocumentNode`)
- `graphql-ws` for subscriptions
- TanStack AI for the test chat, with OpenRouter as the first model provider
- Vitest for unit tests, Playwright for end-to-end flows

## Commands

```
pnpm install
pnpm dev            start the dev server
pnpm codegen        regenerate typed GraphQL documents
pnpm verify         lint, type check, codegen drift check, tests. The gate.
pnpm lint           biome check
pnpm typecheck      tsc --noEmit
pnpm test           vitest run
pnpm e2e            playwright test
```

## GraphQL

- The schema comes from `../server/schema.gql`. Codegen reads that file. This is the only
  thing `web` may read from `server`; never import code from it.
- Write operations in the frontend and run `pnpm codegen`. Generated output is committed
  and never edited by hand. `verify` fails if it is stale.
- **No generated hooks.** Call Apollo's hooks with the generated document, for example
  `useQuery(McpServersDocument)`, and let the types be inferred. Do not pass manual
  generics.
- Convenience hooks such as `useMcpServers()` are thin hand-written wrappers in
  `src/hooks/`.
- Import `ApolloClient` and `InMemoryCache` from
  `@apollo/client-integration-tanstack-start`, not from `@apollo/client`.
- Router setup runs on the server too. Create the WebSocket link only in the browser.
- Handle errors by `extensions.code` from the server, not by matching message text.

## UI

- Use shadcn/ui components. Add one with `pnpm dlx shadcn@latest add <component>`.
- Screens in scope:
  - **Connections:** list, create, edit, delete. Fields: name, URL, auth mode (none,
    token or header, OAuth automatic, OAuth manual), connection mode (read-only, all,
    custom), enabled. Actions: test connection, connect with OAuth, reconnect, re-sync
    tools. Live status badge from a subscription.
  - **Tools:** per connection, with enable or disable and the class (read, write,
    destructive) the admin can override.
  - **Test chat:** see below.
- Secret fields are write-only. Show "set" or "not set"; never display or prefill a value.
- Server icons come from the server as stored image URLs on our own origin. Render them
  only with an `<img>` tag. Never inline SVG from an upstream server.

## Test chat

- The chat runs through a server route. The model key stays on the server and never
  reaches the browser bundle.
- The route opens an MCP client to the gateway's own `/mcp` endpoint and offers the model
  exactly two tools that wrap the gateway's `search` and `execute`. It must exercise the
  same path a real agent uses.
- Show every tool call in the conversation: the queries sent, the tools returned, and
  what was executed with what outcome.
- Model access goes through one small provider module chosen by config, so OpenRouter can
  be replaced later.

## Tests

- Keep component tests few; test components that contain real logic.
- Playwright flows run against the real server, a real database and the fake upstream MCP
  servers. Do not mock the WebSocket for the normal path.
- Tests never call OpenRouter. Use a scripted fake model endpoint.
